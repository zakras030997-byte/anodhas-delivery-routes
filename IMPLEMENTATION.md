# Реализация требований 1.0

Исходное ТЗ — `SPEC.md`. По поручению владельца от 06.11.2026 выполнен поиск официального бесплатного дорожного подключения без готового ключа. Доступы других людей, публично утёкшие ключи и автоматически оплачиваемые API не используются.

## Уточнения реализации

1. Яндекс не выбран: грузовые матрицы и Route Details требуют ключа и коммерческого подключения. Geoapify имеет бесплатный тариф с регистрацией, но готового ключа нет, а фиксированные truck-профили не заменяют требуемые произвольные габариты. Регистрация не выполнялась.
2. Локальный путь работает через официальный публичный Valhalla/FOSSGIS. Введённый собственный сервер — HTTPS API Valhalla, без секретов в URL. Частота запросов общая для всех экземпляров дорожного клиента внутри процесса: интервал 1,15 с.
3. Публичная матрица имеет предел 150 км. Для ≤8 точек предусмотрен расчёт каждой направленной пары через route. Для большего дальнего плана — фиксированный порядок по участкам или свой сервер. До 5 машин/50 операций — предел входных данных, а не обещание доступности публичного API на любом наборе адресов.
4. Минимальная macOS уточнена до 13.3 из-за используемых возможностей системной C++ библиотеки при сборке VROOM. Сборка Universal не означает выполненный запуск на Intel: runtime проверяется отдельно.
5. Координаты ищутся через Apple MapKit, выбор подтверждает пользователь; часовой пояс задаётся и подтверждается пользователем. Исторический/будущий DST вычисляется системной базой времени; повторный час требует явного смещения UTC. Геокодер не обещает автоматического определения пояса.
6. Матрицы строятся для консервативной полной массы машины в пределах вместимости; окончательные участки — с фактическим остатком груза, временем выезда и габаритами. Расписание пересчитывается по окончательным дорогам и проверяется независимо. Живых пробок и доказательства глобального оптимума нет.
7. Ручной порядок сохраняется отдельно. При первом ручном расчёте без распределённого варианта заказы назначаются первой машине; это не автоматическая балансировка. Нарушения вместимости и требований показываются. Перестановка сохраняет назначения предыдущего выбранного варианта.
8. Перерывы задаёт диспетчер. Перерыв без адреса планируется у остановки, без выдуманной стоянки на карте; если он меняет выезд, дорожное ETA запрашивается заново. Юридическая проверка труда/отдыха и подтверждение безопасной парковки отсутствуют.
9. Изменение маршрутообразующих данных или подключения увеличивает revision; предыдущие варианты сохраняются как устаревшие. Финансовые изменения не вызывают дорожный запрос. Поздний ответ не заменяет изменённый план. Отмена затрагивает только собственные запросы и дочерний VROOM.
10. JSON переносит входные данные новой копией с новыми идентификаторами и новым расчётом. Встроенное хранилище сохраняет историю вариантов при перезапуске. Максимум 100 планов/20 вариантов на план и 32 МБ хранилища. Повреждённый файл не перезаписывается автоматически.
11. CSV/PDF относятся к выбранному варианту, содержат статус расчёта, время, поставщика и атрибуцию. Контакты по умолчанию исключены. Матрицы и geometry в JSON относятся к сохранённому расчёту, но импорт не считает их актуальными.
12. До публичного распространения с подключением FOSSGIS надо согласовать использование с оператором; полные условия сайта при исследовании не прочитаны из-за Anubis. Этот этап не включает публикацию или отправку сообщений оператору.

## Воспроизведение проверки

`Scripts/check.sh` запускает ядро, адаптер настоящего VROOM, локальную подмену дорожного клиента, импорт/экспорт и декодирование дорожной геометрии. `Tests/LiveVerification.swift` отдельно проверяет реальный городской и междугородний путь на публичных координатах. Встроенный интерфейс, DMG и установленная копия проверяются отдельно; сборка и локальные подмены не являются их подтверждением.

Исходный VROOM не изменён. Сборка `USE_ROUTING=false` использует внешние матрицы без сетевой библиотеки; исходники зафиксированы commit и submodules. Секретов/токенов в проекте нет; функция ввода платного ключа не показывается, поскольку такой провайдер в этой версии не реализован.
